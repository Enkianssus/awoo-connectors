# QQ 音乐兼容画像

画像只保存版本、模块 SHA-256、机器码前置校验和已验证 RVA，不包含用户数据或播放器文件。

当前 schema 2 连接器仅在版本、三份 DLL 哈希（Client/Common/API）、命名调用约定、目标机器码和全部结构校验同时通过时，才允许调用 QQ 音乐内部的 `AddSongs(mode=0)`。未知版本只生成只读分析报告并拒绝写入进程；历史 schema 1 画像不授权新的 CString/Type4 调用模板。

`22.71.json` 对应 `QQMusic2271.00.25.13` 安装构建，保留精确版本和双 DLL 哈希限制。一次现场《Shelter》插入返回 accepted，用户确认下一首位置正确、原队列保留、没有抢焦点且播放正常；完整范围与限制见 [22.71 验证记录](../../docs/QQMUSIC_22_71_VALIDATION.md)。旧版画像保持保留。

画像包 1.5.0 新增 `22.80.json`，对应 `QQMusic2280.02.25.56`，继续使用 22.76.1 已有的 schema 2 模板，不增加点歌机或连接器最低版本要求。详见 [22.80 验证记录](../../docs/QQMUSIC_22_80_VALIDATION.md)。旧画像文件和冻结的 schema 1 发布入口保持不变。

外部画像通过 `BILINCM_QQMUSIC_PROFILE_DIR` 指定目录。点歌机安装签名包后在启动/刷新连接时选择该目录；schema 2 加载器支持 Reload 并使能力缓存失效，正在执行的事务仍保留自己的不可变画像和安全检查。
